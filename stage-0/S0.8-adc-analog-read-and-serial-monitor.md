## Goal
Read a continuous $0.0\text{–}5.0\text{ V}$ potentiometer voltage on Arduino Uno pin `A0` using the **10-bit Analog-to-Digital Converter (`analogRead(A0)` $\rightarrow$ `0..1023`)**, convert the raw integer count back into volts, and stream live telemetry to the **Serial Monitor** (`9600 baud`).

- **New ideas (max 2):**
  1. **10-bit Analog-to-Digital Conversion (`analogRead` `0..1023` at $5.0\text{ V}$)**: How the Arduino Uno's 10-bit ADC slices the $0.0\text{ V}$ to $5.0\text{ V}$ analog range into $2^{10} = 1{,}024$ steps (`0` to `1023`, $\approx 4.88\text{ mV}$ per step).
  2. **Serial UART telemetry (`Serial.begin` and `Serial.print`/`println`)**: Sending live human-readable numbers from the microcontroller to your computer at `9600 baud` (bits per second) so you are never debugging blind.
- **New syntax (C/C++ on Arduino Uno):** `analogRead(A0)`, floating-point division `5.0 / 1023.0` (using `.0` so C/C++ does not truncate integer division to `0`), `Serial.println(val, 2)` (printing a `float` to 2 decimal places).
- **Target time (unmeasured — [log yours](../.github/ISSUE_TEMPLATE/beginner-timing-log.md)):** Typical: 1.5–2.0 hours | Slow-learner: 2.5–3.0 hours

## Learn

### Idea 1: 10-bit Analog-to-Digital Conversion (`analogRead` `0..1023` at $5.0\text{ V}$)
- **Primary resource:** [SparkFun — Analog to Digital Conversion](https://learn.sparkfun.com/tutorials/analog-to-digital-conversion) `[HTTP 200 — Verified by scripts/check_links.py]`
  - **What to read:** Read exact headings **`The Analog World`**, **`What is the ADC?`**, **`Relating ADC Value to Voltage`**, and **`Arduino ADC Example`**.
  - **What to skip:** Skip `AREF` register reconfiguration details.
  - **Key takeaway:** Digital pins (`0`–`13`) only distinguish `LOW` ($0\text{ V}$) from `HIGH` ($5\text{ V}$). To measure a continuous **analog** voltage—such as a potentiometer wiper at $2.50\text{ V}$—the Arduino Uno routes pins **`A0` through `A5`** into a **10-bit Analog-to-Digital Converter (ADC)**. As you learned in Lesson P.8, 10 bits represent $2^{10} = 1{,}024$ levels (`0` to `1023`), mapping $0.0\text{ V} \rightarrow 0$ and $5.0\text{ V} \rightarrow 1023$ ($\approx 4.88\text{ mV}$ per count).

### Idea 2: Serial UART telemetry (`Serial.begin` and `Serial.print`/`println`)
- **Primary resource:** [Wokwi Docs — The Serial Monitor](https://docs.wokwi.com/guides/serial-monitor) `[HTTP 200 — Verified by scripts/check_links.py]`
  - **What to read:** Read exact headings **`The Serial Monitor`**, **`Arduino Uno and Mega`**, and **`Configuring the Serial Monitor`**.
  - **What to skip:** Skip custom `diagram.json` raw byte-stream overrides.
  - **Key takeaway:** A microcontroller has no screen of its own. Calling `Serial.begin(9600);` in `setup()` opens a text communication line at **9600 bits per second (baud)** between the Arduino and Wokwi's **Serial Monitor** pane. Inside `setup()` or `loop()`, `Serial.print(...)` prints text on the current line and `Serial.println(...)` finishes the line with a newline (`\n`).

### Bridge Notes
Inside the Arduino Uno (`5.0 V`), pins `A0` through `A5` connect to a **10-bit Analog-to-Digital Converter (`ADC`)**. As you learned in Lesson P.8, a 10-bit binary register holds $2^{10} = 1{,}024$ distinct integer codes from `0` to `1023`. Calling `analogRead(A0)` compares the voltage on pin `A0` against the board's $5.0\text{ V}$ supply reference and returns `0` for $0.0\text{ V}$, `512` for $\approx 2.50\text{ V}$, and `1023` for $5.0\text{ V}$.

Using the linear range scaling formula from Lesson P.9, converting an Arduino Uno 10-bit ADC count $\text{adc-raw} \in [0, 1023]$ back into measured voltage $V_{\text{pin}}$ is:

$$
V_{\text{pin}} = \left(\frac{\text{adc-raw}}{1023.0}\right) \times 5.0\text{ V}
$$

**Crucial C/C++ integer division warning:**
In Python (`Lesson P.2`), `512 / 1023` automatically produces a `float` (`0.500488...`). In **C/C++** on Arduino, dividing two integers (`int`) with `/` performs **integer truncation**—discarding everything after the decimal point so `512 / 1023` evaluates to **`0`**! Always write **`1023.0`** and **`5.0`** with decimal points so C/C++ uses floating-point division, and print the result to 2 decimal places using `Serial.print(v_pin, 2)`:

| Potentiometer Wiper Position | Voltage on `A0` ($V_{\text{pin}}$) | `analogRead(A0)` (`0..1023`) | Calculated `(adc_raw / 1023.0) * 5.0` |
| :--- | :--- | :--- | :--- |
| **0% (Full counter-clockwise)** | $0.00\text{ V}$ | `0` | `0.00 V` |
| **50% (Midpoint)** | $2.50\text{ V}$ | `512` | `2.50 V` |
| **100% (Full clockwise)** | $5.00\text{ V}$ | `1023` | `5.00 V` |

## Common mistakes & troubleshooting
- **`adc_to_volts` prints `0.00 V` for every reading except `1023`:** You wrote `(adc_raw / 1023) * 5.0` using integer `1023` instead of floating-point `1023.0`. Always include `.0` when dividing in C/C++.
- **`analogRead(A0)` jumps wildly when nothing is connected to `A0`:** Just like an unconnected digital input, an unconnected analog input pin floats and acts like a tiny radio antenna. Always connect `A0` to a low-impedance voltage source or voltage divider.

## Check yourself

1. **Step size (resolution) of the Uno ADC:** What is the smallest voltage change ($1\text{ LSB}$) that the Arduino Uno's 10-bit ADC ($5.0\text{ V}$ reference, $1{,}023$ steps) can detect, in millivolts (`mV`)?
   <details>
   <summary><strong>Answer</strong></summary>

   $\frac{5.0\text{ V}}{1023} \approx 0.004888\text{ V} \approx \mathbf{4.89\text{ mV}}$.
   </details>

2. **Predicting `analogRead(A0)`:** If a sensor outputs $3.75\text{ V}$ into `A0` on a $5.0\text{ V}$ Arduino Uno, what integer will `analogRead(A0)` return?
   <details>
   <summary><strong>Answer</strong></summary>

   $\frac{3.75\text{ V}}{5.0\text{ V}} \times 1023 = 0.75 \times 1023 = 767.25 \rightarrow \mathbf{767}$ (or `768`).
   </details>

3. **Why `Serial.begin(9600)` is required:** What happens in the Serial Monitor if you call `Serial.println(analogRead(A0));` in `loop()` but forget to put `Serial.begin(9600);` inside `setup()`?
   <details>
   <summary><strong>Answer</strong></summary>

   The Serial UART hardware is never initialized, so the Serial Monitor stays completely blank!
   </details>
