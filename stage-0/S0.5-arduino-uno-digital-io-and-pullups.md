### Idea 2: Digital Input (`digitalRead`), Floating Pins, and Pull-Up Resistors (`INPUT_PULLUP`)
- **Primary resource:** [SparkFun — Pull-up Resistors](https://learn.sparkfun.com/tutorials/pull-up-resistors) `[HTTP 200 — Verified by scripts/check_links.py]`
  - **What to read:** Read exact headings **`Introduction`**, **`What is a Pull-up Resistor`**, and **`Calculating a Pull-up Resistor Value`**.
  - **What to skip:** Skip the bottom internal microcontroller register math if the switch diagram is clear.
  - **Key takeaway:** If you wire a pushbutton between a digital input pin and `GND` with nothing connected to `5V`, then whenever the button is *not* pressed, the pin is connected to nothing at all—a **floating pin** that acts like an antenna and randomly flips between `HIGH` and `LOW`! Enabling the Arduino Uno's built-in internal **pull-up resistor** (`pinMode(2, INPUT_PULLUP)`) connects an internal $\approx 20\text{ k}\Omega\text{–}50\text{ k}\Omega$ resistor from Pin 2 to `+5V`, holding the pin cleanly at **`HIGH` ($5.0\text{ V}$) when released** and dropping it to **`LOW` ($0.0\text{ V}$) when pressed to `GND`** (**active-low** logic).
  - **Alternative resource:** [Wokwi Docs — `wokwi-pushbutton` Reference](https://docs.wokwi.com/parts/wokwi-pushbutton) `[HTTP 200 — Verified by scripts/check_links.py]` — Read exact headings **`Pin names`** and **`Examples`**.

### Bridge Notes
A **microcontroller (`MCU`)** is a single-chip computer combining a processor, memory, and **GPIO** (General-Purpose Input/Output) pins that interact directly with hardware voltages. Unlike Python (which uses indentation), Arduino C/C++ wraps code blocks in curly braces `{ ... }` and ends every statement with a semicolon `;`.

Why did we choose the **Arduino Uno (`5.0 V`)** for Stage 0? Because its $5.0\text{ V}$ logic, 10-bit ADC (`0..1023`), and 8-bit PWM (`0..255`) are completely standardized in Wokwi without board-specific pin-remapping traps. However, remember one hardware safety limit: an Arduino Uno GPIO pin can safely supply at most **$20\text{ mA}$** continuous current ($40\text{ mA}$ absolute maximum)—enough for an LED with a $220\ \Omega$ resistor ($13.6\text{ mA}$), but never a motor!

When wiring a pushbutton to `Pin 2` with `pinMode(2, INPUT_PULLUP);` and connecting the button between `Pin 2` and `GND`, notice that the logic is **active-low**:
- **Button NOT pressed (open switch):** The internal pull-up resistor gently pulls `Pin 2` up to $5.0\text{ V}$, so `digitalRead(2)` returns `HIGH` (`1`).
- **Button PRESSED (closed switch to `GND`):** The button connects `Pin 2` directly to `GND` ($0.0\text{ V}$), so `digitalRead(2)` returns `LOW` (`0`).

       pinMode(2, INPUT_PULLUP); // Button on Pin 2 (HIGH = released, LOW = pressed)
       pinMode(9, OUTPUT);       // LED on Pin 9
     }

     void loop() {
       int button_state = digitalRead(2);
       if (button_state == LOW) {
         digitalWrite(9, HIGH);  // Button pressed -> turn LED ON (5.0 V)
       } else {
         digitalWrite(9, LOW);   // Button released -> turn LED OFF (0.0 V)

     }

## Common mistakes & troubleshooting
- **Using `pinMode(2, INPUT)` instead of `pinMode(2, INPUT_PULLUP)` without an external resistor:** With plain `INPUT`, when the button is released, `Pin 2` is floating (disconnected from both `5V` and `GND`) and will randomly trigger false button presses!
- **Forgetting `pinMode(9, OUTPUT)` inside `setup()`:** If you forget to set an LED pin to `OUTPUT`, it defaults to `INPUT`, so calling `digitalWrite(9, HIGH)` only turns on the weak internal $20\text{ k}\Omega$ pull-up resistor instead of driving $5.0\text{ V}$ strongly, leaving the LED barely glowing.
- **Expecting `HIGH` when an `INPUT_PULLUP` button is pressed:** Because the button is wired between the pin and **`GND`**, pressing the button pulls the pin down to `0.0 V` (**`LOW`**), not `HIGH`!

## Check yourself

1. **`setup()` vs. `loop()`:** If you put `digitalWrite(9, HIGH); delay(500); digitalWrite(9, LOW);` inside `void setup()` and leave `void loop()` empty, how many times will the LED blink after you press the Play button in Wokwi?
   <details>
   <summary><strong>Answer</strong></summary>

   **Once!** `void setup()` executes only **1 time** when the Arduino powers on or resets. To make the LED blink repeatedly, that code must be placed inside `void loop()`.
   </details>

2. **Active-low current draw:** When a button on `Pin 2` (`INPUT_PULLUP`, internal resistor $R_{\text{pullup}} \approx 20\text{ k}\Omega$ connected to $5.0\text{ V}$) is **pressed and held** to `GND`, how much current flows through the internal pull-up resistor to `GND`?
   <details>
   <summary><strong>Answer</strong></summary>

   By Ohm's Law: $I = \frac{5.0\text{ V}}{20{,}000\ \Omega} = \mathbf{0.00025\text{ A}} = \mathbf{0.25\text{ mA}}$—a tiny, completely safe trickle of current!
   </details>

3. **GPIO current limit:** Can you connect a small $5\text{ V}$ brushed DC motor (which draws $300\text{ mA}$ when spinning) directly between Arduino `Pin 9` and `GND` and turn it on with `digitalWrite(9, HIGH)`?
   <details>
   <summary><strong>Answer</strong></summary>

   **Never!** An Arduino Uno GPIO pin can safely supply at most **$20\text{ mA}$** ($40\text{ mA}$ absolute maximum). Drawing $300\text{ mA}$ directly from `Pin 9` will burn out the microscopic output transistor inside the microcontroller chip. (You will learn how to switch high motor currents safely using a MOSFET in Lesson `01.1`!).
   </details>

## Recap
- An Arduino sketch runs **`setup()` once** at boot and repeats **`loop()` forever**, switching digital `OUTPUT` pins between `HIGH` ($5.0\text{ V}$) and `LOW` ($0.0\text{ V}$).
- Configuring a button pin with **`INPUT_PULLUP`** and wiring the button to `GND` prevents floating-pin noise: the pin reads **`HIGH` when released** and **`LOW` when pressed** (active-low).
