# Lesson S0.6: Reading Analog Sensors — The 10-Bit ADC (`analogRead`) & Serial Monitor

## Goal
Read continuous voltages between $0.0\text{ V}$ and $5.0\text{ V}$ on the Arduino Uno's analog input pins (`A0`–`A5`) using its **10-bit ADC** (`analogRead`, returning `0` to `1023`), convert the raw integer back into volts, and stream live telemetry to Wokwi's **Serial Monitor**.

- **New ideas (max 2):**
  1. **Analog-to-Digital Conversion (`analogRead` `0–1023` at `5.0 V`)**: How a 10-bit **ADC** (Analog-to-Digital Converter) slices a continuous $0.0\text{ V}\text{–}5.0\text{ V}$ signal into $2^{10} = 1024$ discrete whole-number steps (`0` to `1023`).
  2. **UART Serial telemetry (`Serial.begin`, `Serial.print`, `Serial.println`)**: Sending live text and sensor numbers from the microcontroller over a serial line at `9600 baud` (bits per second) so you can inspect variables in real time.
- **New syntax:** `analogRead(A0)`, `Serial.begin(9600)`, `Serial.print(...)`, `Serial.println(...)`, `float` division `1023.0` in C/C++.
- **Estimated time (untimed guesses):** Typical: 1.5–2.0 hours | Slow-learner: 2.5–3.0 hours

### Bridge Notes
In Lesson P.4, you learned that a 10-bit binary register holds $2^{10} = 1024$ integer values from `0` to `1023`. The Arduino Uno's **ADC (Analog-to-Digital Converter)** on pins `A0`–`A5` compares an incoming analog voltage $V_{\text{in}} \in [0.0\text{ V}, 5.0\text{ V}]$ against the board's $5.0\text{ V}$ reference and returns an integer `adc_raw` via `analogRead(A0)`:

$$
V_{\text{measured}} = \text{adc}\_\text{raw} \times \frac{5.0\text{ V}}{1023}
$$

Notice the decimal points in `5.0 / 1023.0`! In C/C++ (unlike Python 3), dividing two integers like `adc_raw / 1023` performs **integer division**, which chops off the decimal part and returns `0` for every reading from `0` to `1022`! Always include `.0` (`adc_raw * (5.0 / 1023.0)`) so C/C++ computes a `float`.

*(Note on other boards you may see later: the Arduino Uno is a **10-bit (`0..1023`), `5.0 V`** board. In advanced tracks, 32-bit chips like the ESP32 or STM32 use a **12-bit (`0..4095`), `3.3 V`** ADC. In Stage 0, we strictly use the Arduino Uno's `0..1023` at `5.0 V`!)*

To view your readings live, initialize **UART Serial** in `setup()` with `Serial.begin(9600);` (**baud rate** = bits transmitted per second), then print values in `loop()` with `Serial.print()` and `Serial.println()`.

## Common mistakes & troubleshooting
- **C/C++ integer division trap (`adc_raw * (5 / 1023)` always prints `0.00`):** In C/C++, `5 / 1023` divides two `int` values and truncates the result to `0` before multiplying! Always write `5.0 / 1023.0` with decimal points so C/C++ uses floating-point division.
- **No output in the Serial Monitor:** You forgot `Serial.begin(9600);` inside `void setup()`.
- **All outputs jammed onto a single unreadable horizontal line:** You used `Serial.print(...)` for the last item on the line instead of `Serial.println(...)` (`println` adds the newline character `\n` at the end).

## Check yourself

1. **ADC step size (resolution):** On the Arduino Uno (`0.0 V` to `5.0 V` across `1023` steps), how many millivolts (`mV`) does a 1-count change in `analogRead(A0)` (1 LSB) represent?
   <details>
   <summary><strong>Answer</strong></summary>

   $\frac{5.0\text{ V}}{1023} \approx 0.0048876\text{ V} \approx \mathbf{4.89\text{ mV}}$ per count.
   </details>

2. **Reconstructing voltage:** If `analogRead(A0)` returns `767`, what voltage is present on pin `A0` (rounded to 2 decimal places)?
   <details>
   <summary><strong>Answer</strong></summary>

   $V = 767 \times \frac{5.0\text{ V}}{1023} \approx \mathbf{3.75\text{ V}}$ ($3.7488\text{ V}$).
   </details>

3. **Spotting the C/C++ bug:** Why does `float v = analogRead(A0) / 1023 * 5;` print `0.00` when `analogRead(A0)` is `512`, and `5.00` only when `analogRead(A0)` reaches `1023`?
   <details>
   <summary><strong>Answer</strong></summary>

   Because both `analogRead(A0)` (`int`) and `1023` (`int`) are integers, C/C++ performs **integer division** on `512 / 1023`, which truncates `0.5004` down to the integer `0`! Writing `analogRead(A0) / 1023.0 * 5.0` forces floating-point division and prints `2.50`.
   </details>

- Use **`Serial.begin(9600)`**, **`Serial.print()`**, and **`Serial.println()`** to stream live numbers to the Serial Monitor, and always write `5.0 / 1023.0` with decimal points in C/C++.
